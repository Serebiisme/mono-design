## 目标

为 B 端 Web 提供一套视觉统一、操作明确、容易组合的极简主义组件。通过稳定的组件行为和清晰的文档，支持人工与 AI 连续迭代。

## 已确认的视觉方向

用户于 2026-10-22 选择 Editorial 编辑杂志风（G 版）作为整库最终方向：暖米色与柔黑、衬线标题与无衬线正文、细线、直角、留白及单色状态。正式规则见[设计规范](design-system.md)，选择依据见[决策记录 0003](decisions/0003-editorial-visual-direction.md)。高级能力与后续暗色延展沿用同一方向；实现、校准与验收仍按阶段推进。

## 目标用户与场景

- 前端开发者：组合后台页面，维护表单、列表和反馈流程。
- 设计与产品协作者：核对信息层级、交互状态和场景完整性。
- AI 编程助手：依据统一规范实现组件，减少跨轮次的视觉和行为偏差。

建设范围已由用户选择为全面对标成熟 B 端组件库，覆盖基础组件、复杂表格、日期时间、上传、树与层级选择等高级能力。页面需能适应容器宽度变化；移动端作为后续独立验证范围。

## 极简的含义

- 通过间距、字体和表面色建立层级，控制装饰数量。
- 操作表达直接，同类交互保持一致。
- 默认配置能覆盖常见场景，扩展能力有明确用途。
- 交互状态、错误提示、键盘操作和可访问性保持完整。
- 基础组件只承担通用展示与交互职责。

## 建设范围与分批交付

整库以成熟 B 端组件库的能力覆盖和工程质量为目标。具体公共组件、API、依赖与支持环境在建设计划和工程选型阶段细化，不承诺兼容某个第三方库的 API，也不将组件数量等同于能力完成度。

近期基础验证批次保留以下顺序：

| 阶段 | 内容 | 验证目标 |
| --- | --- | --- |
| 基础体系 | 设计变量、字体、间距、焦点和状态规范 | 建立统一的视觉和交互基线 |
| 第一批组件 | Button、Input、Checkbox、Select、Dialog | 验证操作、输入、选择及弹层能力 |
| 场景补齐 | 按业务预览需要补充基础 Table 和反馈能力 | 验证组合使用与数据状态 |
| 场景验收 | 筛选区、数据表格、弹窗表单组成的后台示例 | 检查完整任务能否顺畅完成 |

第一批组件的具体 API 在对应规范中确定。基础批次只用于尽早验证组合使用；完整建设还包括：

- 通用组件：布局、导航、输入、展示、浮层、反馈及配置能力。
- 复杂表格：排序筛选、固定与分组、展开与树形、编辑、虚拟滚动及组合性能。
- 日期时间：日期与时间、范围、多种选择粒度、本地化及时间值契约。
- 上传：文件队列、并发、取消重试、预览、拖拽及可接入分片续传的适配契约。
- 树与层级选择：懒加载、搜索、关联勾选、拖拽、虚拟化，以及 TreeSelect、Cascader、Transfer 的组合。
- 高级表单：多选与远程搜索、动态字段、联动、异步校验和竞态处理。
- 交付体系：主题与语言扩展、可访问性、文档、组合示例、性能验证、包消费及发布复验。

详细任务见 `docs/plans/component-library-build.md`。上述能力属于已确认的建设方向，具体功能切片和验收参数在对应阶段设计中明确。

## 暂缓事项

- 独立图表平台、富文本编辑器、电子表格式计算引擎和低代码搭建平台。
- 多品牌主题编辑器和专用移动端组件；主题变量、浅暗色适配和语言扩展属于组件库建设。
- 后端接口、账号体系、业务权限和真实数据接入。
- 多框架实现、跨端适配和独立多包发布体系。

新增范围时更新本文与 roadmap，说明它解决的具体使用问题。

## 完成标准

- 纳入整库范围的组件和高级能力均有明确规范、示例、适用状态和验证结果；基础批次通过不代表整库完成。
- 页面在选定的支持环境中能完成筛选、查看和表单提交等示例操作。
- 键盘操作、焦点管理、禁用与加载行为符合规范。
- 空数据、长文本、输入错误和操作失败有可理解的表现。
- 工程检查、浏览器验收及已知限制有实际记录。
