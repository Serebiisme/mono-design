# Mono Design 组件库建设总计划

编制日期：2026-10-22

## 计划性质与目标

本轮交付任务拆分，不执行组件开发、工程初始化或发布。用户已选择全面对标成熟组件库的建设方向，本文据此更新；实际任务状态集中维护在 [roadmap](../roadmap.md)。

以“覆盖成熟 B 端组件体系及高级能力”为建设目标。规划 70 个公共组件、24 项高级能力任务、21 项横向工程与交付任务，共 115 项任务，分为 M0—M12 共 13 个里程碑。

70 个公共组件包含 ConfigProvider、布局与辅助组件，日期范围等作为组件内能力，不重复计数。组件清单是计划基线，具体 API、组合限制和验收参数在 M0 及专项设计中确定；本计划不宣称与任何第三方库完全等价或 API 兼容。

原有 34 项保留编号作为基础批次，新增 C35—C70。原有优先路径继续用于尽早验证，但整库完成还要求高级任务和最终交付验收通过。

## 依据与约束

- [产品定位](../product.md)：桌面后台、极简视觉、完整交互，首期不接真实后端。
- [设计规范](../design-system.md)：Editorial 已定方向：暖米色与柔黑、衬线标题与系统无衬线正文、直角细线、单色反馈及桌面默认密度。
- [工程约定](../engineering.md)：单一组件库工程起步，公共 API、依赖、验证与产物统一。
- [工具协作](../design-tool-workflow.md)：UI UX Pro Max 提供候选和专项建议，Impeccable 用于方案、评审和改进。
- 当前技术栈、支持环境、包名和发布目标均未确定。本计划不预设框架、文件扩展名、依赖版本、公共类型或实际测试命令。
- 当前没有组件源码、可运行预览或构建产物；Git 与远端的实际状态以 roadmap 为准。工具接通不计作组件建设进度。

本计划划分可独立验收的阶段。进入实现前，为相应阶段补齐设计与执行细案：具体文件、API、状态规则、测试断言、实际验证命令及交付边界。任务不跨越未确定的前置决策。

## 完整建设的边界

| 包含 | 后续扩展 |
| --- | --- |
| 桌面后台、中文默认及英文验证、语言资源扩展、容器宽度适应 | 独立移动端体系、全部语言资源维护 |
| 浅色与暗色适配、可覆盖的语义变量 | 可视化多品牌主题编辑器 |
| 动态表单、远程多选、日期时间与范围、高级表格及虚拟化 | 电子表格式公式计算和协同编辑平台 |
| 文件队列、并发、取消重试、预览、分片续传适配契约 | 特定存储服务后台、生产凭证管理、独立图片编辑器 |
| Tree、TreeSelect、Cascader、Transfer 和通用导航展示反馈 | 富文本编辑器、独立图表平台 |
| 本地包消费、文档、发布资料与独立发布验证 | 多框架、多包独立发布、低代码搭建平台 |

分片续传必须提供可验证的模拟服务或参考适配器，真实存储服务接入单独记录。M0 建立能力对照矩阵，以功能切片及组合测试定义完成度；不能仅用同名组件存在或组件总数作验收。

M3—M10 按具体依赖交错推进，里程碑编号不代表必须等整批全部完成才能推进其他任务。完整文档和状态预览随组件交付；M11 负责统一整理与跨组件验证。

用户已选择 Editorial G 版作为最终风格，正式基线见设计规范，历史方案见[探索索引](../design-exploration/README.md)。T08 的文档出口已具备；实际状态统一见 roadmap。T09、T10 的变量实现及实际预览仍按工程依赖推进。每个组件使用工程开发范式中的设计与开发闭环，不因设计工具可用而跳过工程或浏览器验证。

### 关键组件依赖

- Button 先验证变量、公共 API、预览、行为验证与打包消费的整条路径。
- Dialog、Dropdown、Tooltip、Drawer 依赖 T12 的适用浮层能力；避免各自重复处理退出、焦点与层级。
- Select 和 DatePicker 使用浮层基础；Form 依赖字段控件与 T13。
- Table 使用 Checkbox、Pagination、Empty、Spin 等已验收能力。
- Tree 的稳定节点与虚拟化基础用于 TreeSelect 和高级表格；日期组件共用值适配；上传共用任务状态机。
- 高级表格依赖通用表单、树与虚拟化的接口契约，各专项先固定接口再交叉联调。
- Menu 与 Tabs 的键盘模式分别定义，不因外观相近而复用错误语义。
- 非交互容器与展示组件可在视觉基线稳定后逐项推进。

## 优先交付路径

建议先交付一条可用路径，检验规范和工具的实际效果：

M0 → M1 → M2 → Button → Input / Checkbox → 浮层基础 → Dialog / Select → 最小 Form / Table / Pagination → 后台筛选与弹窗编辑示例。

这条路径是基础里程碑。此后完成通用扩展组件及 M7—M10 的四个高级专项，再进入 M11 全量文档与组合验收、M12 质量及发布。基础示例通过不能替代整库完成。

## 单项组件的完成标准

1. 组件规范写明用途、首版范围、API、默认值、状态组合、键盘、边界与限制。
2. 实现与规范一致，复用公共变量和适用交互基础。
3. 提供正常、禁用、加载、错误等适用状态，以及长文本、空内容和窄容器预览。
4. 通过类型、公共行为与必要浏览器验证；不以内部实现细节测试代替用户行为检查。
5. 可从实际构建产物使用，文档示例能运行。
6. 对 Impeccable 提出的实际问题完成取舍和修复，再验证结果；工具建议与实际验收分别记录。
7. 通过后更新 roadmap，保留未验证项，不将计划或规范完成计为组件完成。
