## 何时记录

- 存在多种合理方案，需要说明为何选择其中一种。
- 选择会影响消费方、兼容性、依赖或后续开发方式。
- 调整已采用的关键约定，需要保留变更原因。

普通样式微调和单个组件的常规实现细节放在对应规范或变更记录中。

## 命名与模板

文件使用 `NNNN-short-topic.md`，从 `0001` 开始递增编号。

```md
# 0001 决策标题

日期：YYYY-MM-DD
状态：提议 / 采用 / 被替代

## 背景
需要解决的问题、使用场景及限制。

## 选择
最终方案或当前提议，说明适用范围。

## 原因与备选
考虑过的方案，以及选择当前方案的依据。

## 代价
已知限制、维护成本和受影响的使用方。

## 重审条件
哪些实际变化会触发重新评估。
```

状态按实际进展填写。已采用的决定发生变化时，新增记录并互相链接，在旧记录标注被替代关系；当前规范同步反映有效结论。
