# 0002 全面对标成熟组件库的建设范围

日期：2026-10-22
状态：采用

## 背景

初版计划按通用后台首版提出 34 个公共组件。用户在范围选择中明确选择：“全面对标成熟组件库：包含复杂表格、日期、上传、树等高级能力”。

## 选择

- 将全面对标的能力覆盖作为整库目标，高级表格、日期时间、上传、树与层级选择纳入建设。
- 保持极简视觉，采用基础验证批次、通用扩展、高级专项和整体交付验收的顺序。
- 保留原有 C01—C34 编号，补充 C35—C70、A01—A24，工程与交付任务保留 T01—T21。
- 以能力矩阵、组合验证及实际消费界定完成度，公共 API 保持独立设计。

用户确认的是完整建设方向；70 个组件、24 项高级任务及具体能力切片是据此制定的计划基线。技术栈、实现方案、性能阈值和 API 尚未决定，在 M0 与专项设计中细化。

## 原因与备选

只完成基础组件和简单后台示例无法覆盖本次目标。直接同时铺开全部组件又会放大基础接口变化的影响，因此保留小批次验证路径，再展开高级专项。

## 代价

日期、虚拟化、拖拽、上传和表格组合需要专项设计与验证。整库工作量应按实际能力深度估算，不能按组件数量或简单组件的速度推算。

真实存储服务后台、生产凭证、图表平台、富文本编辑器、电子表格计算引擎及多框架实现仍单独评估；其边界已在产品与计划文档中列明。

## 重审条件

- 目标消费项目、参考库、支持环境或业务任务发生变化。
- 选型或验证发现某些能力组合需要拆分、替换或明确限制。
- 需要调整分批发布边界或增加独立产品级能力。
